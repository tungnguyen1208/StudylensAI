# Change: Video-linked quiz history and failure-safe sessions

- Code: `2026-10-01-v0.5-video-session-history-and-failure-safety`
- Date: `2026-10-01`
- Version: `0.5.0`
- Status: `implemented`

## Reason for change

Learners need to find completed quiz results under the corresponding YouTube
video and learning session. A session must not be labelled completed merely
because playback ended while transcript or quiz generation was unfinished.

## Business behavior: before and after

Before, answer history was a flat list even though quiz, session, and answers
already carried `youtubeVideoId`. `videoEnded` could mark a session completed
before a quiz existed. After, Backend returns the session's video title and a
canonical `/watch?v=` URL with each submitted answer, and the Side Panel groups
answers by video, session, and quiz attempt. Only a successful whole-quiz
submission marks a session completed. A failed transcript or quiz job leaves a
retryable error state; it cannot produce a partial quiz or history entry.

## Architecture decision and rejected alternatives

`youtubeVideoId` is the stable identity stored in existing video, session,
quiz, question, and answer tables. The watch URL is derived from a validated
ID, not stored as mutable duplicated data. Jobs and sessions remain durable
during slow external AI calls; a database transaction cannot span Gemini.
The user chose to retain the minimum failure state for retry. Thus, failure
keeps the session and job error; quiz-generation failure also keeps its
validated transcript as the required retry input. Closing an unfinished
active session removes its session-owned provisional transcript and cues in
one local database transaction. Other videos, sessions, completed attempts,
and shared data are never deleted by this cleanup.

Rejected: deleting the entire failed session (would lose retry), storing a
second URL column, and treating video playback completion as quiz completion.

## Affected contracts, data, and modules

- Assessment History public contract adds optional video title, URL, whole-quiz
  attempt ID, and attempt score to history items; existing response shape and
  contract version remain compatible.
- Session Quiz contract clarifies failure, retry, and completion semantics.
- Backend Session Quiz worker and service enforce failure/closed states,
  discard late AI responses, and clean provisional capture on unfinished close.
- Backend Assessment History checks quiz/session/video identity before grading
  and returns video/session metadata for the Side Panel grouping.
- Additive PostgreSQL indexes support quiz-by-video and answer-by-video/session
  lookup. No business rows or legacy tables are removed by the migration.

## Compatibility and migration

Migration `20261001100000_AddVideoHistoryLookupIndexes` adds three indexes only.
Existing legacy answer rows remain readable. Optional history metadata may be
null when legacy rows lack a matching video or session. No endpoint path,
request DTO, or `0.5.0` version changes are required.

## Risks and limits

The processing saga persists session/job state before calling AI; it is not an
all-or-nothing transaction across Backend and Gemini. A failed quiz retains
the validated transcript to allow retry, but no quiz or answer history is
published. Existing database rows created before this rule are not deleted
retroactively. A live PostgreSQL + Gemini browser smoke run remains necessary.
