# Change: Use the video title to prioritize main-topic quiz questions

- Code: `2026-10-12-v0.5-video-title-main-topic-quiz`
- Date: `2026-10-12`
- Version: `0.5.0` public contract; question prompt `0.5.1`
- Status: `implemented`

## Reason for change

Full-transcript quiz generation could select a grounded but peripheral detail because the AI Service did not receive the title already stored on the learning session. The title is now supplied as a topic hint so candidate questions favor the lesson's central concepts without weakening transcript grounding.

## Business behavior: before and after

- Before: every transcript chunk was evaluated without the video topic, so an isolated name, date, advertisement, greeting or side example could become a quiz question.
- After: every chunk receives the same normalized video title. Gemini is instructed to prioritize concepts, rules, steps, conclusions and recurring ideas that directly explain that topic, and may return no candidates for a peripheral chunk.
- The title is context only. Questions, answers, explanations and cue references must still be supported by transcript evidence.

## Architecture decision and rejected alternatives

Backend passes the stored `StudySession.VideoTitle` in the existing question-generation request after whitespace normalization and a 512-character bound. FastAPI includes it in every existing chunk prompt. No summary call, metadata lookup or additional provider call is introduced.

Rejected alternatives include treating the title as factual evidence, sending the description or channel name, adding a separate topic-extraction request, or relaxing cue-boundary validation.

## Affected contracts, data, and modules

- Private Backend-to-AI question-generation schema and examples add required `videoTitle` and use `promptVersion` `0.5.1`.
- Backend Session Quiz worker supplies and validates the new prompt version.
- FastAPI request validation, prompt construction and tests use the title while preserving provider cue-index mapping.
- Public Extension contract remains `0.5.0`; Extension code and persisted database schema are unchanged.

## Compatibility and migration

Backend and AI Service must be rebuilt and restarted together. Existing quizzes and attempts are not changed. Retried failed quiz jobs keep their original session, transcript, job and idempotency key, but use prompt `0.5.1`. No database migration or Extension repackaging is required.

## Risks and limits

A misleading title may be less useful, so the prompt explicitly resolves title/transcript conflicts in favor of the transcript. Relevance remains provider-dependent and requires a real Gemini smoke test before this entry can become `implemented`.

## Acceptance criteria and test evidence

- Session Quiz contract: 15 tests passed, including required, nonblank and maximum-length title validation.
- Backend: 96 tests passed in the full solution, including title normalization, propagation, prompt-version validation and existing retry/idempotency coverage.
- AI Service: 72 tests passed, including title evidence in every chunk, prompt safety, peripheral empty output, local rejection of date/experiment trivia and unchanged provider-call count.
- Extension: 103 tests passed; typecheck and production build passed.
- Docker release rebuild passed and API, AI Service and PostgreSQL reported healthy. A first real Gemini session found two peripheral questions about a year and an experiment result; the prompt and local relevance gate were tightened from that evidence and redeployed.
- Final live evaluation passed on three topics: a vector lesson produced three central MCQs, a time-management lesson produced five central short-answer questions, and the Claude Skill fallback produced three central MCQs from a Gemini video transcript. Each quiz was persisted, submitted and returned by video-linked history. No extra topic-summary provider call was added.

## SRS/SDS impact

Document that the video title is a non-evidentiary topic hint and the transcript remains the sole factual grounding source. The public API and database model do not change.
