# Change: Gemini short-answer grading and evidence review history

- Code: `2026-10-02-v0.5-gemini-grading-evidence-history`
- Date: `2026-10-02`
- Version: `0.5.0`
- Status: `implemented`

## Reason for change

Week 4 for Dev 3 requires real-LLM short-answer grading with a useful
explanation, persisted answer history, and a direct way to review the evidence
timestamp. Multiple-choice grading must remain deterministic in Backend.

## Business behavior: before and after

Before, FastAPI graded short answers with a deterministic fake only. History
showed the learner's answer and score but omitted the persisted reference answer,
explanation, and evidence action. After, `LLM_PROVIDER=gemini` uses the existing
server-side Gemini adapter with structured output to grade short answers. The
Backend remains the authority for the reference answer and stores the validated
grade only after the whole attempt succeeds. History displays the submitted
answer, reference answer, explanation, and evidence timestamp. Reviewing the
active video seeks immediately; reviewing another video opens its YouTube URL at
the stored timestamp.

If Gemini times out, is rate limited, or returns invalid output, Backend returns
a contract-shaped failure. No quiz attempt, answer-history row, or completed
session is written. The same `clientAttemptId` can be retried after the provider
recovers.

## Architecture decision and rejected alternatives

FastAPI owns prompt construction, provider selection, timeout, and structured
output validation. Backend sends the question, trusted reference answer, and
learner answer; it never trusts a provider to replace the reference answer.
Backend continues to grade MCQ answers locally and calls FastAPI only for short
answers. The `fake` provider remains available for deterministic offline tests.

Rejected: exposing the Gemini key to Extension, sending MCQ grading to Gemini,
persisting partial grades before every question is complete, and opening an
unvalidated arbitrary history URL.

## Affected contracts, data, and modules

- AI grading contract documents provider-backed grading and 400/422/503 error
  envelopes without changing the `0.5.0` request or success response shape.
- Assessment History adds `referenceAnswer` to the submitted-history read model;
  the database already stores this value, so no migration is required.
- FastAPI grading gains prompt, schema, fake-provider, Gemini-provider, timeout,
  and error-mapping layers.
- Backend grading gateway preserves provider error code and retryability and uses
  a timeout longer than the AI grading timeout.
- Extension history renders the complete post-submit explanation and supports
  same-video seek or cross-video timestamp review.

## Compatibility and migration

No database migration, endpoint path, or contract version change is required.
Existing persisted answer rows already contain `ReferenceAnswer`. Consumers of
the `0.5.0` history response must accept the newly documented field. Server
configuration may set `GRADING_TIMEOUT_SECONDS`; the default is 60 seconds.

## Risks and limits

Semantic grading quality depends on the configured Gemini model and available
quota. A provider failure remains retryable only when the provider/AI error says
so. Automated tests use controlled providers and do not prove the quality of a
live Gemini response. Cross-video review opens a new YouTube tab instead of
trying to seek a different video in the current tab.

  on retry.
- Assessment History contract: 6/6 tests passed, including the provider error

- Extension: 79/79 tests passed; TypeScript typecheck and production build passed.
  Evidence URL validation and timestamp conversion are covered.
- A live Gemini grading smoke request was not run to avoid consuming user quota;
  the real adapter path is shared with the already configured Gemini service.

## SRS/SDS impact

Document that short answers are graded by the configured server-side LLM while
MCQ grading remains deterministic, grading is atomic at whole-attempt scope,
provider failures preserve retry without history rows, and history review is
linked to the source video timestamp. This log supports but does not replace the
final SRS/SDS.
