# Change: Release quality hardening and observable processing

- Code: `2026-10-15-v0.5-release-quality-hardening`
- Date: `2026-10-15`
- Version: `0.5.0`
- Status: `accepted`

## Reason for change

The final source and the packaged Extension could drift, the Side Panel showed
fixed percentages that looked like measured progress, and fallback transcript
timestamps could extend past a duration already measured by the YouTube
player. The release also needed one repeatable verification command and safe
timing diagnostics before browser acceptance.

## Business behavior: before and after

- Processing now reports its actual stage and elapsed wait instead of fixed
  percentages such as 75%.
- A known player duration is submitted even when captions are unavailable or
  insufficient. Gemini fallback cues are discarded or clipped at that trusted
  duration before hashing, persistence and quiz generation.
- Closing or changing an incomplete video context now succeeds on PostgreSQL;
  the atomic `SaveChanges` operation replaces an incompatible user-managed
  transaction.
- The release E2E client sends JSON as UTF-8, including Vietnamese video titles.

## Architecture decision and rejected alternatives

The public contract stays `0.5.0` and prompt version stays `0.5.1`. Backend
structured logs record only session/job identifiers, stage durations and safe
result codes. Prompts, transcripts, answers and keys are excluded.

The current title-aware prompt passed the three topic-relevance smokes, so no
second provider call or speculative local ranking layer was added. Fixed
progress bars and accepting Gemini duration over the player duration were
rejected because both communicate data the system does not actually know.

## Affected contracts, data, and modules

- Extension transcript acquisition and Side Panel processing status.
- Backend Session Quiz worker, incomplete-session completion and diagnostics.
- Release verification, Extension package verification and CI.
- No DTO, database migration or public contract change.

## Compatibility and migration

No migration is required. Existing sessions, captures, quizzes, attempts and
history remain unchanged. API and AI containers must be rebuilt; the Extension
must be rebuilt and reloaded to display the stage-based status.

## Risks and limits

Chrome and Edge still require manual sideload/reload evidence. Automated tests
and direct API smokes do not prove browser-specific layout or fault recovery.
For that reason this record remains `accepted` and release tag `v0.5.0` is not
created.

## Acceptance criteria and test evidence

- `release.ps1 verify -Provider fake`: PASS — Extension 106 tests, Backend 97
  tests, AI Service 72 tests, session/quiz contract 15 tests and assessment
  history contract 6 tests; typecheck, production build and ZIP verification
  passed.
- Configured Docker stack: PostgreSQL, AI and API healthy with persisted data.
- Live Gemini caption MCQ: 3/3 main-topic questions for a 591000 ms vector
  lesson.
- Live Gemini caption short answer: 5/5 main-topic questions for a 1235000 ms
  time-management lesson.
- Live Gemini URL transcript fallback: 137 bounded cues and 3/3 main-topic
  questions for a trusted 577000 ms duration; maximum cue end was 577000 ms
  and maximum evidence end was 543785 ms.
- Fallback persistence contained one transcript capture, one quiz and the two
  expected jobs (`transcriptGenerate`, `quizGenerate`). The jobs succeeded in
  about 37.0 s and 4.5 s respectively.
- Attempt submission and video-linked history were exercised for all three
  quiz shapes. Manual M-01 through M-08 remain pending on Chrome and Edge.

## SRS/SDS impact

No architecture or public-requirement change is required. Operational text may
describe stage-based progress and trusted video-duration bounding.
