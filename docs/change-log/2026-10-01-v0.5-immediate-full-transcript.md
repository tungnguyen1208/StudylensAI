# Change: Acquire the full YouTube transcript on video open

- Code: `2026-10-01-v0.5-immediate-full-transcript`
- Date: `2026-10-01`
- Version: `0.5.0` (schema unchanged)
- Status: `implemented`

## Reason for change

The Extension could hash cues in a different order from Backend, producing `transcriptHashMismatch`. A rendered YouTube transcript panel can contain only currently visible rows; accepting it after 100 characters could create a quiz from incomplete evidence. Learners should not need to play a video to its end before a full caption track is submitted.

## Business behavior: before and after

- Before: direct caption metadata was attempted once, a 100-character DOM slice could be uploaded, and the Extension hash could disagree with the submitted cue order.
- After: while StudyLens is ON, a supported `/watch` page first retries caption metadata within a bounded window and fetches the entire Timedtext JSON3 track, or XML if JSON3 fails. The Extension sends one canonical full-video payload as soon as the track is available, regardless of playback position. Short but complete direct tracks are accepted.
- A DOM transcript is preview-only until rows settle and their cue span is checked against the player duration without a large gap. If completeness is not established within eight seconds of entering DOM fallback, the Extension submits `insufficient` without cues so Backend can start the existing Gemini fallback. The sidepanel labels local cues as a YouTube preview until Backend marks the transcript ready.
- A video transition, OFF, or departure from `/watch` disposes the old reader; stale reads and old package responses cannot replace the new video state. Upload retry resends the prepared payload and idempotency key.

## Architecture decision and rejected alternatives

- Keep `captionTracks -> Timedtext JSON3 -> XML -> DOM` in the Extension. Backend remains the source of truth for validated transcript, job, quiz, and history; FastAPI receives the full transcript in one Backend request. FastAPI may internally partition long content for Gemini.
- Reject watched time or a fixed character threshold as proof that a DOM transcript is complete. Reject uploading a partial DOM slice merely because it is visible in YouTube's drawer.
- Canonicalize text, remove empty cues, and sort by `startMs`, then `endMs` before both hashing and upload. Backend validates before reserving the session idempotency key so a corrected request can be retried after a hash error.

## Affected contracts, data, and modules

- Contract `contracts/public-api/session-quiz.yaml` clarifies canonical SHA-256 and `durationMs`; shared cross-language fixture: `contracts/examples/session-quiz/transcript-hash-canonical.json`. No endpoint, request shape, or version change.
- Extension: video-activation transcript service/content script, YouTube transcript reader/adapter, sidepanel preview state.
- Backend: transcript validation ordering in `LearningPackageService`. Existing capture and quiz-job persistence stays unchanged.
- AI Service: no code or public contract change; existing full-video quiz route remains in use.

## Compatibility and migration

No schema migration is required for this change. Existing PostgreSQL worktree changes are preserved. Previous transcript captures and quiz attempts remain readable. Previously rejected hash uploads can be retried with a new session or, if no submission was persisted, with the corrected canonical payload.

## Risks and limits

- DOM coverage is a conservative heuristic, not a proof that YouTube returned every word; when duration or coverage cannot be established, Gemini fallback is used.
- YouTube can change caption metadata/Timedtext access. Gemini fallback still depends on a configured AI provider and a public video.
- The browser Extension and running Backend must be reloaded/restarted to use these edits. Live Chrome video-transition and real Gemini-provider smoke tests were not completed in this verification run; do not treat unit tests as proof of those external paths.

## Acceptance criteria and test evidence

- Shared unordered/whitespace/empty-cue fixture has the same hash and canonical cues in Extension and Backend. Backend test also confirms a bad hash does not reserve the idempotency key, and the corrected submission is accepted with one quiz job.
- Extension tests cover full JSON3 at playback start, XML fallback, delayed caption metadata, short complete direct tracks, DOM gap rejection, stale/disposed direct reads, and retry identity.
- `npm.cmd test` in `apps/extension`: 76/76 passed; `npm.cmd run build`: passed, including TypeScript and content-script verification.
- Backend `SessionQuiz.Tests`: 6/6 passed after the last Backend edit; other Backend suites passed in an isolated `TranscriptVerify` build (`VideoActivation` 10/10, `AssessmentHistory` 11/11). Isolation was required because the running Backend briefly locked the default Debug DLL.
- `python -m pytest -q` in `services/ai`: 46/46 passed. No live Gemini call was made.
- Live Chrome smoke remains pending: the attached Chrome internal Extensions tab cannot be controlled through the available browser surface to reload the unpacked Extension; the previously running Backend was no longer listening at `localhost:5000` during verification.

## SRS/SDS impact

Record that full YouTube captions are acquired on video open without watch-time gating, DOM is preview-only until full-span verification, and a canonical cross-language hash is part of transcript validation. SRS/SDS source files were not modified.
