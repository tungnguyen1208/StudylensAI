# Change: Report Gemini quota failures without repeated quiz requests

- Code: `2026-10-01-v0.5-gemini-quota-handling`
- Date: `2026-10-01`
- Version: `0.5.0` (contract shape unchanged)
- Status: `implemented`

## Reason for change

Live quiz jobs remained at the sidepanel's fixed 75% stage and eventually showed `providerFailed`. A controlled provider probe returned HTTP 429 `RESOURCE_EXHAUSTED` for `gemini-3.8-flash`, but the Gemini adapter checked only `status_code`; the installed SDK exposes this status as `code`. The Backend immediately retried the quota failure up to three times, and the SDK also retried internally.

## Business behavior: before and after

- Before: a depleted Gemini quota appeared as a generic provider error after long waits and repeated requests.
- After: the AI Service returns `providerRateLimited` with a safe message and `retryable: true`. Backend persists the failed step after its first quota response, without automatic immediate retry. The sidepanel explains that the learner should try again after quota renewal and retains the manual retry action. No quiz is presented as ready while quota is exhausted.

## Architecture decision and rejected alternatives

- Backend remains the owner of durable jobs and retry policy. The Gemini SDK is configured for one attempt; quiz generation uses its structured `generate_content` path, which returned the quota error promptly in a controlled probe. Public-video transcript fallback retains its existing YouTube-capable Interactions path.
- Ordinary caption tracks up to 24,000 text characters use one Gemini quiz call; longer tracks can still be split internally. A 14,420-character capture that previously required two calls now fits in one.
- Reject silently changing the model, adding a browser-side provider call, faking a quiz, or retrying a quota failure immediately. The user/provider must restore quota or change their server-side plan/configuration before a real Gemini quiz can succeed.

## Affected contracts, data, and modules

- No endpoint, DTO shape, schema version, or database migration changes. The AI and public session-quiz contracts document `providerRateLimited` in their existing string error code fields; a contract fixture covers the retryable envelope.
- FastAPI Gemini adapter, quiz and transcript-fallback error handling; Backend learning-package worker; Extension sidepanel error copy.

## Compatibility and migration

Existing sessions, transcript captures, and jobs remain intact. Running AI Service, Backend, and unpacked Extension must be restarted/reloaded to adopt the new code. Existing historical `providerFailed` records are not rewritten.

## Risks and limits

- This change does not increase Gemini quota. A real quiz still cannot finish until the provider accepts a generation request.
- Several active sessions for the same video were present in the live database. The worker processes one queued job at a time; this change does not delete or reassign those sessions.
- Structured output after quota renewal and an end-to-end browser quiz remain unverified against the live provider.

## Acceptance criteria and test evidence

- Live read-only model lookup confirmed `gemini-3.8-flash`; a controlled `generate_content` probe returned HTTP 429 `RESOURCE_EXHAUSTED`. The patched adapter classified a controlled 429 as `providerRateLimited` in approximately 0.3 seconds without exposing the raw provider response.
- AI Service: 55 tests passed with `LLM_PROVIDER=fake` scoped only to the test process; the production `.env` remained configured for Gemini. A controlled probe using the full quiz output schema reached Gemini and returned the correctly classified HTTP 429 in approximately 0.6 seconds.
- Backend Release test solution: 33 tests passed (SessionQuiz 12, VideoActivation 10, AssessmentHistory 11). The Debug build was locked by the running Backend, so Release was used for isolated verification.
- Extension: 76 tests, TypeScript typecheck, and production build passed.
- Session-quiz contract: 14 fixture/schema tests passed, including the new retryable quota error.
- Live Gemini quiz success and Chrome sidepanel smoke remain pending until quota is available and services/Extension are reloaded.

## SRS/SDS impact

Document rate/quota failure as a distinct recoverable processing state, with no automatic immediate retries and no fabricated quiz. Keep Backend-owned durable jobs and server-only Gemini credentials.
